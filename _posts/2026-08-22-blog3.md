## Project Background

#### What is a Device Tree?

The Linux kernel needs to know what hardware it's running on, but a lot of embedded hardware is undiscoverable: unlike PCI or USB devices, it can't announce itself at boot. Device Tree is a data structure used by the Linux kernel to describe such hardware, including CPUs, buses, memory regions, and peripherals. 

This description is written in .dts files for a specific board, with .dtsi files holding properties shared across a family of boards or an SoC, much like a C header. These source files are compiled by the Device Tree Compiler (dtc) into a binary blob, the .dtb, which the bootloader loads into memory alongside the kernel image. At boot, the kernel parses this DTB and matches each node's compatible property against registered drivers to bind the right one, all driven by data instead of hardcoded board files.

#### Device Tree Bindings and DT Schema

For this to work, every driver and every .dts file need to agree on what properties a node should have, and that agreement is a DT binding: the spec for a given compatible string, defining its required/optional properties, types, and constraints. Bindings are effectively the ABI between the Device Tree and the kernel driver, so they need to stay stable once merged.

Historically They used to be written as free-form .txt files, which nothing enforced against actual .dts content, so errors often only showed up as boot failures. That's why bindings are now being migrated to YAML Schema using the dtschema tooling, so tools like dt-doc-validate and make dtbs_check can catch mistakes automatically at build time.

#### my goal for this project

With that context, my GSoC project was to convert as many of the remaining legacy .txt Device Tree bindings to the dtschema format as possible.

## Project Report

The core of my project involved converting legacy text bindings to DT schema. I mainly worked with bindings of hardware from Texas Instruments (TI). While converting bindings I often had to fix existing dts/dtsi files as well. Apart from that, I also fixed a critical bug in the irq-crossbar driver.
